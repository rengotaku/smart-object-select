# ADR 0002: 非同期待機中の入力変更を世代カウンタで無効化する

## 背景

この機能は**待つ処理だらけ**で、しかも待っている間もユーザーが操作できる。

- image encoder: WASM 実行で数秒〜数十秒
- mask decoder: 1 秒未満だが即時ではない
- 画像ファイルのデコード: 画像サイズに比例（大きい写真ほど遅い）
- ONNX モデルと WASM ランタイムのダウンロード: 合計 20MB 超

この間にユーザーは「別の画像を選ぶ」「別の場所をクリックする」ができる。何も対策しないと、**後から完了した古い処理が最新の状態を上書きする**。

このクラスの不具合は次の性質を持つ:

- **例外が出ない**。古い結果も型としては正しいので、そのまま表示される
- **通常フローのテストは緑のまま**。競合を明示的に駆動しないと再現しない
- **画面上は「それらしく」見える**。前の画像のマスクが新しい画像に重なっても、マスクの形が不自然なだけで壊れて見えない

実際、codex レビューで検出された指摘 11 件のうち 6 件がこのクラスだった。実装と test を同じ視点で同時に書くと、両方が同じ盲点を持つため検知できない。

## 決定

**非同期処理をまたぐ状態には世代カウンタ（generation counter）を持たせ、await 明けに世代が変わっていたら結果を破棄する。**

系統ごとに独立した世代カウンタを持つ:

**表1: 世代カウンタの配置**

| 場所 | 何を守るか | 破棄の方法 |
|---|---|---|
| `samSession.ts`（Worker 側） | 保持している embedding がどの `setImage` に属するか | 世代が古ければ `SamStaleRequestError` で reject し、内部状態を上書きしない |
| `useSegmentation.ts`（main 側） | 表示中のマスクがどの画像に対応するか | 世代が古ければマスクを反映しない |
| `ImageDropzone.tsx`（main 側） | 通知するデコード結果がどの選択に属するか | 世代が古ければ `onImageLoaded` を呼ばず、objectUrl を解放する |

判定の基準は「最新のリクエスト世代」ではなく「**保持しているデータが属する世代**」にする。前者だと `setImage` の**準備中**（世代は進んでいるが embedding はまだ古い画像のまま）を検出できず、新しい画像の座標に対して古い画像の embedding で推論してしまう。

チェックは **await のたびに入れる**。`decode()` の後だけでは、その後の `postProcessMasks()`（画像サイズへの補間を含む非同期処理）の間に起きた差し替えをすり抜ける。

**世代を進めるのは「新しい入力を受けた時点」であり、その入力が妥当かどうかの判定より前**にする。無効なファイルを選んだ分岐で世代を進め忘れると、拒否のエラーを表示したまま、先に進行していたデコードが完了して勝手にその画像へ遷移する。

**アンマウント時にも世代を進める**。遷移後に解決した結果が通知されるのを防ぐ。

## テストの扱い

この種の競合は**手動で解決できる Promise（deferred）で駆動する**。`setTimeout` や `await Promise.resolve()` でタイミングを作らない（実行順が処理系依存になり flaky になる）。

```ts
function deferred<T>() {
  let resolve!: (v: T) => void;
  let reject!: (e: unknown) => void;
  const promise = new Promise<T>((res, rej) => { resolve = res; reject = rej; });
  return { promise, resolve, reject };
}
```

「開始 → 入力を変更 → 解決」の順で駆動し、**記録・送信された値が開始時点のもの**であることを固定する。

## 捨てた案

**処理中は UI を `disabled` にして操作させない**
付け忘れで穴が復活し、無関係な入力欄まで固まる。また「画像を選び直す」は本来いつでもできてよい操作で、待たせるのは UX の劣化。**結果を捨てる**方を選んだ。

**最新のリクエスト世代だけを見る**
`setImage` の準備中を検出できない。実際にこの実装で codex から指摘を受けた（保持データ自身の世代と突き合わせる形に修正）。

**AbortController で処理をキャンセルする**
transformers.js の推論は中断できず、Worker のメッセージ往復にも中断機構が無い。「止める」のではなく「捨てる」しかない。

**`useEffect` の cleanup フラグ（`let cancelled = false`）だけで済ませる**
コンポーネントのライフサイクルには効くが、同一マウント内で入力が変わる競合には効かない。両方必要で、世代カウンタが本体。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 世代カウンタの実装形式（`useRef` の数値、モジュールスコープの変数など）。破棄の判定が同じなら形式は問わない
- **変えてよい**: stale と判定したときの挙動のうち、**ユーザーへの見せ方**（現状は静かに捨てるか `SamStaleRequestError` で reject する。エラーとして画面に出さないのは「画像を差し替えただけで障害に見える」のを避けるため）
- **壊すと危ない**: **await のたびのチェックを削ること**。1 箇所でも抜けると、そこが窓になって古い結果が通る
- **壊すと危ない**: 判定基準を「保持データの世代」から「最新リクエストの世代」へ戻すこと
- **壊すと危ない**: 世代を進める位置を、入力の妥当性判定より後ろへ動かすこと
- **壊すと危ない**: 競合テストを deferred から `setTimeout` へ書き換えること。flaky になった結果 skip されると、保証が静かに消える
- **壊すと危ない**: stale と判定した結果の `objectUrl` を解放し忘れること（破棄と解放は対で行う）
